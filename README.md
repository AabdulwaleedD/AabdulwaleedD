# 📚 How I Approach Projects

I believe good technical work starts with understanding the problem before writing code.

My typical workflow is:

**Understand the problem → Define the rules → Inspect the data → Clean and validate → Design the solution → Build → Test → Document → Improve**

I pay particular attention to:

- Data quality
- Business rules
- Reproducibility
- Maintainability
- Automation
- User experience
- Clear documentation
- Practical usefulness

I don't want to build software simply because I can write code. I want to understand **why the system is needed, who will use it, what problem it solves, and how it can be maintained.**
